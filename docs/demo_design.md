## Как показать

1. QA: рабочий стол → первый диалог → критерий → доказательство.
2. Оператор: рабочий стол → своя оценка → объяснение и возможность апелляции.
3. Тимлид: сотрудник → повторяющаяся ошибка → пример разговора.
4. Комплаенс: сигнал → контекст → существующий процесс расследования.
5. Руководитель QA: стандарт → версия и изменения; директор: общий обзор.
6. Администратор: доступ, настройки и история действий.

Тест смысловых изменений и запуск оценки моделью расходуют бюджет API; для репетиции сначала используйте уже сохранённые результаты. Изменение только весов можно пересчитать без вызова модели.


## Проверка рабочих сценариев и офисный стиль — 7 ноября 2026

Инспектор теперь состоит из двух отдельных панелей с заголовками, отступом и скруглениями: разговор и оценка. Сообщения оформлены отдельными блоками; выделение связывает критерий с репликой. Убраны крупные антиквенные заголовки, уточнены размеры текста и нейтральная офисная палитра. Итоговый балл виден при открытии, без автоматической прокрутки списка вниз. На узком экране открытие критерия оставляет пользователя у объяснения; переход к реплике выполняется отдельной кнопкой доказательства.

| Роль | Проверенный сценарий | Устранённая неясность |
| --- | --- | --- |
| QA | Очередь → критерий → исправление с причиной → публикация; решение по апелляции | После сохранения понятно, что нужна публикация. После публикации — подтверждение и явный следующий переход |
| Оператор | Опубликованная оценка → ознакомление → выбор оспариваемой оценки → причина → отправка → решение | Ознакомление не скрывает возможность апелляции. Форма причины открывается в видимой области, есть переход к отслеживанию |
| Тимлид | Сотрудник → его диалоги → пример → возврат к сотрудникам | Фильтры не переносятся между ролями, виден контекст выбранного сотрудника |
| Комплаенс | Конкретный инцидент → разговор → тот же инцидент → в работу → решение → закрытие | Ссылки открывают нужное дело, а не общий список |
| Руководитель QA | Черновик → изменение весов → сохранение → публикация → пересчёт старых диалогов | Разъяснено отличие публикации стандарта от обновления прежних оценок |
| Директор | Аналитика → пример по критерию → просмотр оценки → риски | Проверен просмотр без элементов редактирования |
| Администратор | Новый сотрудник → настройки → импорт JSON без оценивания → аудит | Импорт по умолчанию не запускает платную модель |

Проверка выполнена Playwright/Chromium: 9 сценариев для 7 ролей, без ошибок JavaScript. Изменение весов завершилось с 0 вызовов модели. Проверены светлая и тёмная темы инспектора, ширина 390 px без горизонтального переполнения; меню закрывается при сужении окна. Неоднозначные отметки времени mm:ss больше не интерпретируются как часы для обвинения в долгой паузе.

Тест `scripts/ux_walkthrough.cjs` требует `UX_TEST_URL`, `PLAYWRIGHT_MODULE`, `UX_CHROMIUM` и проверяет служебный endpoint `/api/ux-isolation` до любых изменений. Обычный сервер такого endpoint не имеет. Для теста использована отдельная схема PostgreSQL, а вызов модели заблокирован. Начальный запуск ошибочно попал на занятый порт основной демо-базы; тестовые изменения восстановлены транзакцией из снимка, совпадение всех 12 бизнес-таблиц проверено. Затем полный прогон выполнен на подтверждённо изолированном сервере. Записи входов в аудите сохранены.

Ограничения: проверены основные рабочие пути, а не все комбинации ошибок, прав и данных. Качество оценок модели, платная переоценка и аудио не проверялись. Это UX-проверка демо, не сертификация production.

## Личное развитие оператора

Экран «Мои результаты» обновлён по отдельному макету: приветствие и реальные поля профиля, показатели, дневная динамика, сильные/слабые стороны, рекомендации по ошибкам, сравнение периодов и новые оценки. По умолчанию выбран текущий месяц по сегодняшний день; предыдущий период имеет такую же длительность. Пунктир на графике сопоставляет дни периодов по их порядку, не заполняя дни без оценок. При отсутствии прошлого периода сравнение не вычисляется.

Результат критерия — средняя доля от его максимального ответа, в процентах; N/A и флаги риска исключены из рейтинга навыков. Грубые ошибки отображаются отдельным показателем. Рекомендации основаны на стандартных критериях, не генерируются моделью; ссылки ведут к собственным диалогам с выбранной ошибкой. Город не показывается, поскольку такого поля в профиле нет. Языки определяются по доступным диалогам.

Проверки: `scripts/operator_ui_check.cjs` и `scripts/operator_growth_check.cjs` — реальный интерфейс и подменённые данные для расчётов (шкала, бинарные ответы, N/A, прошлый период, пустая база сравнения). Изменений бизнес-данных нет.
