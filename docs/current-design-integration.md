# Объединение бизнес-функций и утверждённого дизайна

Основа интерфейса — main 111fa16 (включая f294102). Серверные улучшения перенесены из codex/business-completion fa33b46. Страницы QA, оператора, руководителя, вход и CSS сохранены из main.

## Изменения
- Атомарные операции оценки/апелляций, проверка прав на неопубликованные оценки, история опубликованных версий, защита параллельных операций.
- Расчёт аналитики по версии чек-листа соответствующей оценки. Публикация нового чек-листа не переписывает исторические результаты.
- Задачи из существующей формы руководителя связаны с кабинетом оператора: назначение → ответ → возврат/принятие → синхронизация статуса плана. История попыток сохраняется. Старые персональные планы переносятся при однозначном сопоставлении активного оператора и группы. Общегрупповые планы остаются у руководителя.
- В меню оператора и руководителя добавлен раздел «Развитие», у администратора — «Интеграция». Сохранены текущая оболочка и навигация.
- Добавлен Dataverse pull-адаптер. Кнопка импорта недоступна до настройки соединения. Deep link Dynamics разрешается сервером после входа с проверкой прав.
- Исправленная по апелляции оценка снова требует ознакомления. Форма апелляции требует выбрать реплику-доказательство.

## Проверки на Windows
- 8 unit/contract tests: расчёты, доступ и Dataverse с MockTransport.
- 10 integration tests в одноразовой БД: в том числе связка формы руководителя с оператором, возврат на доработку, повторное выполнение, подтверждение и изоляция чужих задач.
- 6 проверок ролей и отдельная проверка lead в изолированной схеме.
- Browser: четыре роли, 24 основных маршрута, 390px, создание задачи через утверждённую форму, ответ оператора, подтверждение руководителем и reload, апелляция, решение QA, ознакомление с пересмотренной оценкой, ошибка сети, блокировка сотрудника и отзыв сессии.
- Отдельные 9 экранов руководителя: фильтры, переходы, форма обратной связи и состояния апелляций.

Все AI-вызовы заменены тестовыми ответами/заблокированы. Реальный Claude API не проверялся и не вызывался. Браузерные записи выполнялись только на одноразовой тестовой БД.

## Запуск и ограничения
Рабочая БД не использовалась для тестов. Пример для отдельной проверки: DATABASE_URL указывает на отдельную БД, затем python -m app.seed и python -m uvicorn app.main:app --port 8004. Для режима без AI задайте ANTHROPIC_API_KEY=preview-disabled и ANTHROPIC_BASE_URL=http://127.0.0.1:9. Не копируйте эти значения в конфигурацию финального AI-прогона.

Перед обновлением существующей БД сохраните резервную копию. Миграции не удаляют оценки, планы и пользователей; исторические роли отключаются. Уникальные индексы остановят запуск при старых дубликатах текущих оценок/открытых апелляций — такие данные требуют отдельной сверки.

Открытые ограничения: legacy-связь диалогов с оператором по имени; миграция на стабильный operator_id ещё нужна. Dataverse не проверен с реальным tenant: нужны настройки, разрешения и контракт; отсутствуют incremental cursor и восстановление прерванного sync. Обратная передача оценок и SSO не заявлены реализованными. Отдельные записи обратной связи руководителя пока остаются в его карточке сотрудника; оператор получает задачи и комментарии к их проверке. Полная production-готовность не заявляется.

Дополнительно проверена миграция на отдельной копии текущей базы: сохранены 65 диалогов, 109 оценок, 1 апелляция и 53 пользователя. Повторный запуск миграции не создаёт дубликаты задач. Исходная база при этой проверке только читалась через pg_dump.
