# Матрица приёмки Freedom Quality

Источник обязательных требований этой работы — задание пользователя. Первичные PDF ТЗ/Student Guide отсутствуют; docs/критерии_оценки.md — пересказ. docs/demo_design.md отсутствует. Исследовательский roadmap не принят за обязательное ТЗ. Ниже результаты локальных проверок, не разрешение production deployment.

|Приоритет / требование|Пользователь / результат|Реализация|Проверка / статус|
|---|---|---|---|
|P0 доступ к оценкам|Оператор — свои публикации; lead — своя группа|Общий контроль detail/evaluation, persisted published marker, фильтр истории|HTTP: чужие/неопубликованные ID 404, группа изолирована; опубликованная история после апелляции доступна. Пройдено для текущей модели данных|
|P0 четыре роли|QA/op/lead/adm|Права, UI, seed; legacy роли мигрируют неактивными с сохранением IDs|HTTP migration test; четыре роли в браузере; lead не отзывает/решает апелляцию. Пройдено|
|P0 идентичность при ручном импорте|Оператор получает именно свои данные|Dynamics имеет явный mapping внешнего сотрудника → login; legacy dialogs.operator остаётся именем, обычный import угадывает имя из транскрипта|Остаётся переход ручного импорта и связей dialogs на стабильный user ID; одинаковые имена при admin-создании/смене роли отклоняются. Не закрыто полностью|
|P0 атомарность и повторы|QA/op без частичных записей|Вложенные транзакции, advisory lock, уникальные текущая оценка/открытая апелляция; планирование/retry сериализованы|Rollback при отказе уведомления, параллельный submit 200/409, повтор задания оценки и retry. Пройдено|
|P0 версия решения/история|QA исправляет нужную оценку|409 для устаревшей апелляции, строгие boolean, новая версия при override, published history|HTTP решение сохраняет исходный ответ; публикация нового чек-листа не меняет оценки. Пройдено|
|P0 расчёты|QA/руководитель получают корректные числа|N/A, веса, шкала, отдельный flag; историческая аналитика и калибровка по версии|8 unit/contract tests; устранены инверсия yes/no в потерях и активные веса для истории. Реальная точность AI не проверялась|
|P1 цикл оценки|QA → оператор|Import → fake model → review → confirm → acknowledge; неполная оценка не публикуется|Изолированная PostgreSQL и HTTP; браузерная публикация. Пройдено с подменой AI|
|P1 апелляция|Оператор/QA/lead|Критерий, аргумент #реплика, решение, пересчёт, история и уведомления|HTTP и браузер: подача/решение/revised acknowledge. Пройдено|
|P1 развитие|Руководитель/оператор|Назначение, ответ, возврат/подтверждение, persistence, история попыток, уведомления|HTTP изоляция/идемпотентность; браузерный цикл и reload. Пройдено для основного цикла; отдельный browser-return сценарий не проверен|
|P1 Dynamics data|Администратор|Dataverse pull, env mapping, нормализация, external IDs, дедупликация, retry, журнал, UI|MockTransport и isolated DB пройдены. Live tenant заблокирован. Incremental cursor для >100 страниц ещё не реализован|
|P1 Dynamics embedding|Все роли|Deep link и ?dynamics_id с authenticated resolver и серверными правами; same-site iframe способ описан|Context API проверен. Реальный web resource/SSO/cross-site iframe не проверены/не завершены: нужны tenant и контракт|
|P1 обратная отправка|Заказчик|Не подтверждена первичным ТЗ|Не реализована; нужны требования и целевая схема|
|P1 метрики/ожидание|QA/lead/op|Период, выборка, исторические потери, фактическая очередь, задачи; бизнес-эффект описан отдельно|HTTP пустой/невалидный период и историческая версия. Нет вымышленных SLA/сроков; causal до/после и повторные ошибки как отдельная когортная метрика не реализованы|
|P1 воспроизводимость|Разработчик|Репозиторные install/start/check, pinned Playwright|Чистая копия, новый venv/PG на той же Debian 13: установка, seed, pip check, smoke и 8 unit/contract tests прошли. Новая машина не проверялась|
|P2 браузер|Четыре роли|Существующий стиль; новые рабочие разделы|24 маршрута, 390px mobile render, без pageerror; network error; admin revocation. Это не полный аудит доступности|

Остаются локальные работы: стабильная идентичность ручного импорта; расширенные сценарии возврата задач/восстановления синхронизации и очереди после аварии; incremental Dynamics для больших наборов; согласованное когортное измерение повторных ошибок. Не объявлять все P0/P1 закрытыми.

Внешние блокеры: исходное ТЗ и согласованные правила автопубликации/порогов; Dynamics tenant, schema, app registration и секреты; GitHub API Forbidden для PR. Git push работает. Live AI запрещён пользователем.
